Direct Send SMTP Setup

leadsnextgencentre.online · step-by-step, do these in order
1

Check outbound port 25 is open on the VPS

This is the one thing that silently breaks everything else — many hosts block outbound port 25 by default to fight spam, and direct-send needs it (there's no alternate port for server-to-server mail delivery).

Open a Hostinger support ticket (or live chat) and ask: "Is outbound TCP port 25 open on my VPS at 187.52.121.165? If not, please unblock it for SMTP mail delivery." Do this before anything else — no point configuring DNS if port 25 is blocked.
2

Add DNS records in Hostinger hPanel

Go to hPanel → Domains → leadsnextgencentre.online → DNS / Nameservers → DNS Zone Editor. Add these 5 records one at a time using the normal "Add Record" form. Your existing records (root A, NS, www) stay untouched — you're only adding new ones.

TypeNameValue / Priority
Amail187.52.121.165
MX@mail.leadsnextgencentre.online, priority 10
TXT@v=spf1 mx ~all
TXTleads._domainkeysee DKIM value below ↓
TXT_dmarcv=DMARC1; p=none; rua=mailto:info@leadsnextgencentre.online

3

Set the PTR (reverse-DNS) record

Your VPS's IP 187.52.121.165 needs to reverse-resolve to mail.leadsnextgencentre.online. This is set at the hosting/IP level, not in the domain's DNS zone.

Go to hPanel → VPS → your VPS → Network settings / rDNS. If you don't see the option, ask Hostinger support in the same ticket from step 1: "Please set the PTR record for 187.52.121.165 to mail.leadsnextgencentre.online."

Skipping this is the #1 reason direct-send mail gets rejected outright by big providers (especially Microsoft) — don't skip it even if it feels optional.
4

Deploy the updated code on your VPS

SSH into your VPS and run:

cd /path/to/leads-dashboard
git pull origin main
npm install
npm run build
pm2 restart leads-dashboard

Replace /path/to/leads-dashboard with wherever the app actually lives on the box.

5

Configure the Email settings in the dashboard

You're already on the right screen (Email Management → SMTP Server Credentials tab, with the Direct Send (Built-in) card selected — the rocket icon). From here, do this in order:

  1. In HELO Hostname * (currently empty, showing grey placeholder text "e.g. mail.leadsnextgencentre.cloud" — that's just a placeholder, not a real value), click in and type mail.leadsnextgencentre.online
  2. Sender Display Name can stay as LEADS Next Gen Centre — no change needed.
  3. Sender Email Address * currently shows leadsmsruasnextgencentre@gmail.com — clear that and replace with info@leadsnextgencentre.online. This has to be on the same domain as the DKIM/SPF records or authentication won't line up.
  4. Click DKIM Signing (Advanced) to expand that section (it's currently collapsed with a down-arrow next to it).
  5. Fill in the three fields that appear — Domain, Selector, Private Key — using the table and key block below.
  6. Click Save SMTP Credentials (bottom-right of the form).
  7. On the right panel, Test Recipient Email already has kayo2970@gmail.com filled in — leave it, then click Test Connection & Send Email and check the result that appears below the button.

DKIM Private Key — a real 2048-bit RSA key was generated for this domain and delivered to the Super User directly in chat (never written to disk in this repo, and never should be — anyone with this key could sign mail as this domain). If it needs regenerating, run:

openssl genrsa -out dkim-private.pem 2048
openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt -in dkim-private.pem -out dkim-private-pkcs8.pem
openssl rsa -in dkim-private.pem -pubout -outform PEM -out dkim-public.pem

Paste dkim-private-pkcs8.pem's contents into the dashboard's Private Key field, and derive the DNS TXT value from dkim-public.pem (strip the header/footer lines and concatenate the base64 body after v=DKIM1; k=rsa; p=).

6

Optional: sender logo (BIMI) not required to send mail

The LEADS logo (converted from the SVG added to the repo) is published at https://leadsnextgencentre.online/bimi-logo.svg (public/bimi-logo.svg). To make it appear as the sender's profile icon in supporting mail clients, add one more DNS TXT record:

TypeNameValue
TXTdefault._bimiv=BIMI1; l=https://leadsnextgencentre.online/bimi-logo.svg;
Two real limits, not bugs: (1) BIMI only activates once DMARC is enforced at p=quarantine or p=reject — it's currently p=none (monitor-only) on purpose, so the logo won't show until that's deliberately tightened after confirming mail authenticates cleanly for a while. (2) Gmail specifically requires a paid Verified Mark Certificate (~$1,300+/year, needs a registered trademark on the logo) to show the logo at all — without it, this only works in Yahoo Mail and a few smaller clients.
7

Wait for propagation, then test

Give DNS 15–30 minutes to propagate. Then in the same Email settings page, use Test Connection & Send Email — send to a Gmail address you personally control first, before trying an @msruas.ac.in address. Check whether it lands in inbox or spam, and share the result — the dashboard's diagnostic panel will show the raw SMTP response either way.
